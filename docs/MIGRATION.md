# 安装前检查、迁移与回滚

本轮没有安装插件。以下留给后续独立测试与正式切换。

## 先做隔离试用

1. 备份当前 XPI 与本机配置。数据库备份必须在 Zotero 正常关闭后或用一致性备份方式完成，不能只复制活动的 sqlite 主文件。
2. 使用独立 Zotero profile 和测试数据目录，安装预览 XPI。首次保持待机，检查菜单、显示、评分解析、父条目归一化和 Note 识别。
3. 设置本机端点和密钥，用“检查模型列表”验证可访问性。该检查不等于推理已验证。
4. 选择一篇测试文献，检查完整全文，再将该测试实例设为 executor，恢复队列并手动补齐 L1。
5. 测试 L2/L3、已有旧 Note、标签修复、在途取消、暂停、重启及 Note 编辑/同步后标记保留。检查 AI Butler 手动摘要是否保持 LF Note 不变。

## 唯一执行端移交

先暂停旧端、处理在途任务，再关闭所有可能处理相同范围的旧 Butler 自动扫描。关闭扫描不等于清空在途队列。确认数据和文件同步完成，才在新端建立只读基线并启用自动化。

默认仅个人库。首版不提供跨设备锁；`AI:Lx` 或运行标签都不能作为互斥锁。克隆整个 profile 会连同角色一起复制，必须人工将新端恢复待机，禁止双 executor。

## 缺全文或历史结果待核对

- 多份 PDF：在来源绑定区选择主文附件 key。
- 已保存的 MinerU Markdown：确认对应主文且内容完整后，填写其附件 key；不会调用 Butler 的私有解析函数。
- 缺全文或部分索引：下载附件、完成既有解析/索引后，等待原任务复查。无需反复创建新任务。
- 只有完成标签、未知格式或多份冲突：不自动重算，先人工核对。
- 已知旧 Note 与 Butler 共享归属：可明确创建 LF 保护副本，原 Note 保留。未创建保护副本时，另一个插件仍可能修改旧 Note。

## 回滚

先暂停 LF 并关闭自动化，再停用插件。保留本地状态目录和普通 LF Note。之后才恢复旧插件及其配置，并先检查新 LF Note，避免旧自动化重复处理。

0.3.0 使用新偏好命名空间；回到 0.2.1 前要特别检查旧版本的自动开关，不能以为新版本的待机设置约束了旧版本。

## 后续未覆盖

动态提示词包导入、群组库设置 UI、自动 MinerU 调用、视觉分析、多个执行端、Zotero 10 原生多选分类均不在本次预览验收范围内。不要将模拟测试通过当作这些能力已就绪。
