# 0.5.0 自动 L1 补漏

P520 的 Zotero 同步会保留条目在源设备上的 `dateAdded`。旧版本用该时间判断“是否为新条目”，导致自动化开启后才同步到 P520、但源添加时间较早的论文被写入基线却没有创建 L1 任务。

0.5.0 做了三项修复：

- 初始基线仍保护启用前已经存在的历史文献；启用后凡首次出现在执行端基线中的条目均视为新条目，不再依赖跨设备 `dateAdded`。
- 每 5 分钟轻量核对基线与评分，并在启动、恢复和重新启用自动化后立即核对，补偿暂停期间或通知丢失造成的漏单。
- PDF 已下载但全文索引缺失、不完整或过期时，先调用 Zotero 原生完整索引；同一文件版本 15 分钟内不重复触发索引。索引仍不可用时继续保留等待任务，不调用模型。

升级不重建初始基线，不会批量处理启用前的历史条目。P520 现场修复只移除经审计确认的、自动化启用后有修改且无任何 Literature Flow 任务的 5 个条目基线记录，使其由新逻辑重新进入队列。
