# 自动 L1 队列恢复 · 0.4.8

## 现场问题

2026-10-25 在 P520 检查到自动化已开启，但 123 条任务中有 113 条处于等待状态，其中 107 条仍显示 `paused`。插件每 5 秒检查一条任务；等待 PDF 或全文索引的队首任务每 30 秒再次到期，可能长期抢在队尾任务之前，导致后来加入的文献看起来没有触发 L1。

最近加入队列的 12 条记录实际上已经建立自动 L1 任务，但这些 Zotero 条目没有子附件。逐题核对后，12 条均与库中已有条目重复；已有条目带 2 个附件，而新条目为 0 个附件。因此新条目本身无法提供 `PDF_TEXT`，即使轮到检查也会进入“缺少 PDF”。

## 修复

0.4.8 增加两项队列恢复行为：

- 恢复自动化或重启活动执行端时，把 `waiting / paused` 任务恢复为明确的 `queued` 状态。
- 在所有到期任务中优先检查最久未检查的任务，避免短周期重试的队首任务饿死后续任务。

插件仍只在 PDF 全文完整可用时调用模型。缺少附件或全文索引不完整的任务只等待，不消耗模型请求次数。
