# 0.4.4 分散笔记整合与清理

## 行为

- 仅处理用户当前选择的文献或分类范围，并在确认前显示文献数、来源笔记数和同级重复组数。
- 只识别带 `AI-Generated`、`AI-Summary`、`AI-DeepRead` 的有效 AI Butler 结果，或带有效 `LF_RECORD_V1` 记录的 Literature Flow 笔记。
- 按 L1 → L2 → L3 生成一条综合笔记。每一级存在多条结果时，按 Zotero `dateModified` 选择最新结果；日期相同时使用稳定的条目 ID 和 key 决定顺序。
- 综合笔记继续带 `AI-Summary`，可由原版 AI Butler 的“总结 → AI 总结”识别和预览。
- 所有明确识别的分散来源笔记在私有 JSON 备份成功后移入 Zotero 回收站。未明确识别的笔记保持原样。
- 全程不调用模型。综合笔记正文由 Markdown 渲染为 Zotero 原生 Note HTML，可继续编辑，也可导出为 Markdown。
- 正文只保留论文内容和 L1/L2/L3 层级。标题下的操作说明、旧笔记标题、供应商/模型/时间、输入方式提示和生成记录都会移除；工作流身份保存在执行端私有状态中，不写入 Note 正文。

## 安全与恢复

每篇文献写入前都会将当时的全部子笔记保存到 Zotero profile 下的 `literature-flow-v1/note-backups/`。清理使用 Zotero 的删除标记，因此来源笔记仍可从回收站恢复。整合事务开始前还会重新读取条目和笔记；选择后发生的变化会使写入中止。
